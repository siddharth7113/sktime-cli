# H06 — Hierarchical forecast and serialization audit

> Reviewer-only detail. Never place this file in model context.

## Why this is hard

The agent must notice that the named dataset preserves hierarchy during fit,
while the same data serialized as long CSV is not reconstructed as hierarchical
by default inspection.

## Reference observations

The source manifest has 240 rows. Direct named-dataset fitting succeeds with
cutoff 2004-12. There are four bottom series and three forecasts per series:

| Product line | Product group | 2005-01..2005-03 value |
|---|---|---:|
| Food preparation | Hobs | 119 |
| Food preparation | Ovens | 178 |
| Food preservation | Freezers | 137 |
| Food preservation | Fridges | 173 |

The JSON prediction exposes all 12 MultiIndex tuples. The forecast CSV is
written successfully, but default `data inspect` reports `Series`,
`pd.DataFrame`, shape 12x4 with flattened hierarchy columns.

## Critical review points

- Fitting from the flattened CSV instead of the named dataset loses the tested
  preservation route.
- The answer must separate successful hierarchical prediction from lossy CSV
  re-ingestion metadata.
- No aggregate reconciliation should be claimed or inferred.
